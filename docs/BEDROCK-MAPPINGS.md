# Bedrock mappings (Geyser + Rainbow)

Bedrock players join through Geyser, which doesn't read Java resource packs. Without these files
they would see SlashSlabs' terrain slabs as the vanilla states Polymer borrows for them (sculk
sensors for bottom slabs, waxed copper slabs for top slabs) and the Track Smoother as a stick.

The files, all generated by Rainbow:

| File | What it is |
| --- | --- |
| `config/Geyser-Fabric/custom_mappings/geyser_block_mappings.json` | Overrides the borrowed vanilla states with SlashSlabs geometry and textures |
| `config/Geyser-Fabric/custom_mappings/geyser_item_mappings.json` | The slab items and the SlashRails Track Smoother |
| `config/Geyser-Fabric/packs/tbs-custom-content.zip` | The Bedrock resource pack (gitignored as `*.zip`: add it with `git add -f`) |
| `config/Geyser-Fabric/locales/overrides/en_us.json` | Item names |

`enable-custom-content: true` in `config/Geyser-Fabric/config.yml` must stay on.

## These go stale

The block mappings name exact vanilla states (for example `minecraft:sculk_sensor[power=3,...]` is
grass slab tint 0). Polymer hands those states out in registration order, so the mappings are only
right for the mod set they were generated against. **Regenerate after any change to SlashSlabs,
SlashRails, StreamCraft, or any other mod that uses Polymer blocks or items**, then check
`report.txt` for problems.

## Regenerating

1. Export the server pack (`python ../server-config.py build`) and run it locally
   (`python ../bakeoff/bakeoff.py serve A-dense <seed> --full`).
2. Join with a 26.2 Fabric client that has only Fabric API and Rainbow (Prism instance
   `Rainbow-26.2`; Rainbow from Modrinth, project `rainbow-mod`). Accept the server pack.
3. Give yourself every custom item: `slashrails:track_smoother` and each `slashslabs:*_slab`.
4. In chat: `/rainbow create tbs`, `/rainbow auto blocks`, `/rainbow mapinventory`, `/rainbow finish`.
5. Copy from `.minecraft/rainbow/tbs/`: `custom_mappings/geyser_block_mappings.json` and
   `geyser_item_mappings.json` into `config/Geyser-Fabric/custom_mappings/`, `pack.zip` to
   `config/Geyser-Fabric/packs/tbs-custom-content.zip`, and `lang/en_us.json` to
   `config/Geyser-Fabric/locales/overrides/`. Then `packwiz refresh`.
6. Boot the pack and check the log for `Registered N custom block overrides` and
   `Registered N custom items`.

Last generated 2026-10-05 with Rainbow 0.2.1-26.2-b55 against TBS-Server 2.0.0 (SlashSlabs 0.2.1,
SlashRails 0.3.0, StreamCraft 0.28.6): 34 block mappings, 12 item mappings. Geyser registered 233
block overrides, 12 custom blocks and 13 custom items. One known gap: StreamCraft's Display Block
has an empty model (it draws through display entities, which Geyser doesn't support), so Bedrock
shows it as a sculk sensor. Not yet checked with a real Bedrock client.
